# CosyVoice3 runtime

Каталог содержит HTTP-сервис синтеза речи и адаптер CosyVoice3. Он собирается отдельно от API приложения: модель использует Python 3.10 и PyTorch 2.3.1+cu121, основной API — Python 3.15. Сервис вызывается через `inference.tts_base_url`.

Код CosyVoice закреплён на `074ca6dc9e80a2f424f1f74b48bdd7d3fea531cc`, веса FunAudioLLM/Fun-CosyVoice3-0.5B-2512 — на `29e01c4e8d000f4bcd70751be16fa94bf3d85a18`. `requirements.lock` фиксирует модельное окружение; `runtime-extras.lock` — дополнительные зависимости HTTP-сервиса и JSON-кодек orjson. Образы uv и CUDA закреплены digest.

Штатная сборка и запуск выполняются из корня проекта:

```powershell
docker compose up --build -d
```

Отдельная сборка образа:

```powershell
docker build -t switch-vox-core-tts:local deploy/cosyvoice
```

## HTTP-контракт

`GET /health` возвращает готовность модели и образца голоса, флаг `busy`, параметры PCM и числовой профиль синтеза. `busy` остаётся включённым до завершения активного worker, включая его отмену. До загрузки модели сервис отвечает HTTP 503.

`POST /synthesize` принимает `{ "text": "Короткая фраза" }`: текст после удаления пробелов по краям должен содержать от 1 до 500 символов; лишние поля запрещены. Голос выбирается при запуске сервиса. Пока текущий синтез не завершён, следующий запрос получает HTTP 409.

Успешный ответ — поток `audio/pcm`: PCM16 little-endian, один канал, 24000 Гц. Заголовки `X-Sample-Rate`, `X-Channels`, `X-Sample-Width-Bytes` описывают формат. Аудио передаётся кадрами длительностью не более 20 мс; очередь содержит не более четырёх кадров. Промежуточный WAV не создаётся.

## Модель и образец голоса

Одна модель остаётся в памяти между запросами. ONNX-подготовка образца работает на CPU; генерация речевых токенов, flow и vocoder — на CUDA GPU. Из конфигурации загрузки исключены компоненты обучения. Русский текст передаётся токенизатору без китайского или английского normalizer. Текст и аудио не записываются в эксплуатационные логи.

Для своего голоса задайте одновременно `TTS_REFERENCE_WAV` и `TTS_REFERENCE_TEXT` в корневом `.env`. Первое значение — путь к WAV внутри контейнера, например `/models/fixtures/reference.wav`; второе — точная расшифровка записи без префикса CV3. Сервер добавляет префикс сам. Каталог хоста `data/fixtures` доступен как `/models/fixtures`. Используйте запись, разрешённую для такого применения.

Если оба значения пусты, используется штатный `asset/zero_shot_prompt.wav` из CosyVoice с соответствующим текстом. Если задана только одна переменная, запуск отклоняется до загрузки весов. Смена образца требует пересоздания контейнера TTS и проверки речи и задержки:

```powershell
docker compose up -d --no-deps --force-recreate tts
```

Сервер работает от UID/GID 10001 с `HOME=/home/vox` и отдельным cache-каталогом. Веса `/models` монтируются только для чтения. Порт модели на хост штатным Compose не публикуется.

## Отмена и профиль синтеза

Закрытие HTTP-ответа устанавливает сигнал отмены независимо от готовности первого аудиокадра и заполнения очереди. Генерация токенов и flow/vocoder используют общий compute-lock. Готовый flow блокирует следующий token step до получения аудиоблока на CPU. Ожидания проверяют отмену с шагом до 10 мс; уже запущенный CUDA kernel не прерывается из Python.

После завершения или ошибки синтеза поток речевых токенов останавливается и буферы запроса очищаются. Если он не остановился за 2 с либо HTTP-worker не остановился в срок очистки, процесс завершается с кодом 70. Нормальное завершение и подтверждённая отмена сохраняют веса в памяти.

`/health.progress` содержит числовые счётчики и времена текущего или последнего запроса:

- `first_token_us` — первый принятый речевой токен;
- `first_flow_us` — начало первого `token2wav`;
- `first_audio_us` — готовность первого непустого блока после переноса на CPU;
- `first_pcm_us` — окончание преобразования этого блока в PCM;
- `llm_done_us` и `finished_us` — завершение генерации токенов и очистки синтеза.

Эти отметки отсчитываются в микросекундах от начала модельного потока. `frontend_us` отдельно измеряет подготовку входа. `first_flow_finalize=1` означает финальный первый вызов flow для короткой фразы; ноль — потоковый вызов. Незавершённые стадии не получают фиктивных нулевых отметок. Профиль сбрасывается для нового запроса, а `finished_us` включает паузы потребителя и очистку.

Дополнительных CUDA-синхронизаций профиль не вводит: времена включают ожидание и существующую CPU-копию. `TTS_PROFILE=1` включает запись числового профиля в лог; по умолчанию она выключена. `RUNTIME_LOG_LEVEL` задаёт уровень журнала модельного сервиса (по умолчанию `INFO`); `DEBUG` добавляет этапы и сводные счётчики запросов. Сообщения передаются в stderr через фоновую очередь; при остановке очередь дожидается завершения записи.

## Проверки

Проверка очереди и отмены без модельных зависимостей и CUDA из корня проекта:

```powershell
uv run python -m unittest deploy.cosyvoice.test.test_streaming
```

Остальные тесты в `deploy/cosyvoice/test` выполняются в модельном окружении: они проверяют HTTP-очистку, конфигурацию образца голоса, жизненный цикл генерации токенов, ошибки flow и сброс профиля. Нейросетевые вычисления в этих тестах заменены детерминированными CPU-операциями.

Диагностика конкуренции речевых токенов и flow использует фиксированные входы и проверяет их хеши. CPU-тесты проверяют жизненный цикл и очистку; качество речи, задержка и потребление VRAM проверяются отдельно с загруженными весами.
